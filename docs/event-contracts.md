# Event and workflow contracts · v0.1

Audit envelope: `id` UUID, `tenant_id` UUID, `actor_id` server-derived identity/service ID, `event_type`, `resource_id`, JSON `details`, UTC `created_at`. Event types include demo initialization, proposal creation/approval/rejection, command verified/aborted/quarantined/retry, account kill-switch changes, source refresh, diagnostics, and outcome ingestion/correction. Audit rows are append-only; personal data and secret values are prohibited.

Proposal states: `pending → rejected | queued`; queued execution ends `verified | aborted | quarantined`. A retry keeps command status queued with an available-at backoff and persisted attempt. Dead-letter commands are quarantined and create critical alerts. No public endpoint retries or compensates a quarantined command automatically.

Source snapshots: immutable ID, tenant/customer/resource, observed-at and source-at, account-local date, currency, completeness, attribution maturity, normalized state and metrics. Demo daily spend/clicks and mature 30-day qualified CPA use different windows. Mature CPA equals synthetic mature cohort spend divided by finalized cohort leads; `sampleSize` refers to historical clicks. Live ingestion must independently reconcile these fields before storage.

CRM outcomes: canonical external ID per tenant, account, stage, finality, revenue/cost integer micros, currency, event-time and ingestion-time. Corrections require a strictly newer event-time and explicit correction flag; audit preserves before/after financial values. Current model stores canonical state plus audit corrections. Offline conversion events have separate upload status and consent; upload transport is not implemented.

The source contract and policy schemas are exported from `src/core/contracts.ts`; CRM schema from `src/server/outcomes.ts`. OpenAPI is generated by `npm run contracts:generate`. Unknown object fields are rejected. Request actors/roles are never accepted from the client.
